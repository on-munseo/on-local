# 서식 채우기 재현 — 원래 서식은 그대로 두고 칸의 글만 바뀌는가

npm 꾸러미 `on-munseo-local`(On 문서 내 PC 판)의 서식 채우기(`on_fields` → `on_fill`)가 서식을 얼마나 건드리는지 재는 대본입니다. 재는 것은 「값을 넣은 칸 말고는 아무것도 바뀌지 않았는가」입니다. 대상은 법제처 국가법령정보센터에 공개된 법령 서식·별지 709개입니다.

- 우리가 만든 대본으로 우리가 잰 값(자체 측정)입니다. 대신 대본·출처 목록·결과 지문을 모두 실었습니다. 공개 npm 꾸러미와 공개 파일만으로 누구나 같은 숫자를 다시 낼 수 있습니다.
- 비공개 코드는 쓰지 않습니다. 문서 파일은 이 폴더에 싣지 않고, 원 출처 주소와 SHA-1 만 싣습니다.

## 다시 재는 순서

Node.js 20 이상이 있으면 됩니다. 다른 꾸러미는 깔지 않습니다.

```sh
node run.mjs --selftest        # 견주기가 헐겁지 않은지 — 허락한 바뀜 7가지는 통과, 일부러 망가뜨린 본문 17가지는 잡는지(24가지 모두 「맞음」이어야 함)
node run.mjs --limit 50        # 앞의 50개만(법제처에서 받기 — 파일 사이 0.3초 쉼)
node run.mjs                   # 709개 모두(약 24MB 받기 — 파일 사이 0.3초 쉬어 6분쯤, 받아 둔 뒤 돌리기는 맥북에서 35초 안쪽)
```

- 처음 돌리면 `sources.json` 의 주소에서 파일을 받아 `cache/` 에 두고 SHA-1 을 맞대 봅니다. 원 출처의 파일이 바뀌었으면(법령 개정 등) 그 문서는 「받기 실패」로 적고 넘어갑니다.
- 꾸러미는 `npx -y on-munseo-local@0.3.2` 으로 받아 띄웁니다(`--pkg` 로 다른 판). 꾸러미는 인터넷을 쓰지 않습니다. 대본이 문서를 받을 때만 인터넷을 씁니다.
- 끝나면 `out/result.json`(문서마다 갈래·개수·지문)과 `out/files/`(만든 HWPX — 한글로 직접 열어 볼 수 있음)가 생깁니다. 전부 돌렸을 때는 `expected/summary.json` 과 숫자·지문을 자동으로 맞대 봅니다.
- 내 서식으로: `node run.mjs --files 목록.txt`(한 줄에 경로 하나). 문서는 이 컴퓨터 밖으로 나가지 않습니다.

## 어떻게 견주나

1. **고르는 칸.** `on_fields` 가 찾은 칸 가운데, 지금 값이 빈 칸을 앞에서부터 셋 고릅니다. 날짜 칸에는 `2026. 11. 27.`, 그 밖의 칸에는 `○○시 보건정책과`·`홍길동`·`○○구 ○○로 12` 를 차례로 넣습니다. 안 고른 고르는 칸이 있으면 첫째 하나를 고릅니다.
2. **기준.** HWPX 서식은 원본 파일 그대로를 기준으로 씁니다. 예전 한글(.hwp)은 `on_fill` 이 HWPX 로 바꾼 뒤 채우므로, 같은 꾸러미의 `on_to_hwpx` 로 바꾼 HWPX 를 기준으로 씁니다. 이 대본은 「채우기가 바꾼 것」을 잽니다.
   - .hwp 를 HWPX 로 바꾸는 것 자체가 얼마나 충실한지는 이 대본이 재지 않습니다.
   - 다만 .hwp 원본을 읽은 글과 바꾼 HWPX 를 읽은 글은 580개 모두 글자·숫자가 같았습니다. 그림 자리 이름만 다릅니다.
3. **zip.** 항목 이름·차례·압축 방식, `mimetype` 이 맨 앞이고 압축하지 않았는지, 본문 밖 항목이 바이트까지 같은지 봅니다.
4. **본문 XML.** 태그·글 토막 단위로 차이(Myers)를 구합니다. 덩이마다 위 여섯 갈래 가운데 하나인지 봅니다. 속성 하나라도 바뀌거나 태그가 빠지면 「그 밖」입니다.
   - 글을 바꾼 덩이는 옛 글(빈칸 뺌)이 새 글 안에 차례대로 남아 있어야 합니다. 남지 않은 글자가 있으면, 그 덩이의 문단에 넣은 값이 들어 있고, 옛 글이 도구가 알린 자리 표시 글과 이어지고(한쪽이 다른 쪽 안에 듦), 그 글자가 모두 그 자리 표시 글의 글자 몫 안일 때만 「자리 표시 갈아 끼움」이고 아니면 「그 밖」입니다.
5. **글자 수지(빈칸 뺌).** 본문 글 전체에서 빠진 글자 0이어야 합니다. 값 말고 더해진 글자 0, 넣은 값 가운데 안 들어간 글자 0이어야 합니다.
   - 날짜 칸은 서식의 「년·월·일」 글자와 「20  년」의 「20」을 두고 숫자만 넣으므로, 그 글자는 다시 넣은 것으로 치지 않습니다(날짜 값 수만큼만).
   - 「자리 표시 갈아 끼움」으로 본 덩이의 옛 글 속 자리 표시 글자만 그 몫 안에서 빠져도 됩니다(`guide_chars`). 다른 문단의 빠짐이나 몫 밖의 빠짐은 그대로 「빠진 글자」입니다.
6. **다시 읽기.** 만든 파일을 같은 꾸러미의 `on_read` 로 다시 엽니다. 넣은 값이 보이는지, 기준과 견주어 값 말고 글자·숫자가 바뀌지 않았는지 봅니다.

5와 6을 모두 넘어야 「원래 서식 그대로」입니다. `--selftest` 는 아래 24가지로 견주기를 시험합니다.

- 허락한 바뀜 일곱은 통과해야 합니다: 빈 칸에 값·고르는 칸·그 문단 줄 자리 기억, 새 문단, 날짜 칸, 「20  년」을 살린 날짜 칸, 같은 문단에 값 덩이(그 문단의 글자 모양), 빈 문단에 값 덩이(header.xml 의 글자 모양), 도구가 알린 자리 표시 갈아 끼움.
- 아래 열일곱은 잡아야 합니다: 속성 바뀜, 글자 빠짐, 값 말고 다른 글 더함, 값을 넣지 않은 문단의 줄 자리 기억 지움, 글자 모양 덩이 사라짐, 「년·월·일」 지우고 덮음, 날짜 숫자가 덜 들어감, 값 덩이에 그 문단에 없던 글자 모양, 같은 문단 두 곳에 없던 글자 모양 덩이(서로 정당화), 값 덩이에 다른 속성, 글이 빠지기만 함, 알린 자리 표시 밖의 글자까지 지움, 자리 표시 몫으로 다른 문단의 글을 지움, 자리 표시 「-」 몫으로 값이 들지 않은 문단의 「-」를 지움, 알리지 않은 자리 표시 지움, 빈 문단·새 문단의 값 덩이에 header.xml 에 없는 글자 모양 번호.

## 한계

- **자체 측정입니다.** 고르는 칸과 넣는 값을 우리가 정했습니다. 사람이 실제로 채울 칸과 다를 수 있습니다. 예를 들어 별표 표의 머리 칸 옆 빈칸도 「칸」으로 잡힙니다.
- **자리 표시로 알린 글은 값으로 바뀝니다.** 이번 709개에서 도구가 자리 표시로 알리고 갈아 끼운 글은 「○○○」·「OOO (인)」처럼 이름 자리인 것 말고도 「-」(7곳)·「제 호」(문서 번호 틀, 5곳)·「( )」·「의」(1곳)·「(… 기재)」 같은 안내 괄호가 있었습니다. 도구가 미리 알리므로 이 대본은 「그대로」로 셉니다. 다만 「제 호」·「의」처럼 서식의 글자가 사라지는 경우가 있으니, 알림(`note`)을 보고 값을 넣을지 정해 주세요.
- **채울 곳을 맞게 찾았는지, 값이 뜻에 맞는 칸에 들어갔는지는 재지 않습니다.** 이 대본은 「다른 것이 바뀌지 않았는가」를 봅니다. 위 「다른 1개」처럼 자리가 어긋나 글자가 더해지면 잡지만, 엉뚱한 빈칸에 값만 정확히 들어간 경우는 사람이 봐야 압니다.
- **한컴 한글로 연 모습은 이번에 보지 않았습니다(확인 안 함).** 줄 자리 기억을 지운 문단은 한글이 열 때 줄을 다시 나눕니다. 값이 길면 칸 높이·쪽 나눔이 바뀔 수 있습니다. 이것은 채우기라면 어떤 도구에서나 생기는 일입니다.
- **이 측정의 0.3.1 결과는 HWPX 입니다.** .hwp 가 필요하면 한글에서 열어 .hwp 로 저장합니다. **0.3.2 npm 게시 전 묶음**의 `on_fill` 은 원래 .hwp 서식이면 다시 읽어 채운 글과 같을 때 HWPX 와 .hwp 를 함께 줍니다(`replace`·`cells` 포함, `as` 기본 `both` · `as: "hwpx"` 면 HWPX 만). 맞추지 못하면 HWPX 만 주고 까닭을 알립니다. 원래 .hwpx 와 다른 도구는 그대로 HWPX 만입니다([0.3.2 바뀐 점](../../CHANGELOG.md#032--2026-11-28-npm-게시-전-묶음)). 위 709개 측정은 0.3.1 기록 그대로입니다.
- **이 측정의 0.3.1 은 미리보기를 바꾸지 않습니다.** `Preview/PrvText.txt`·미리보기 그림이 그렇습니다. 그래서 파일 탐색기의 미리보기에는 채우기 전 모습이 보일 수 있습니다. 0.3.2 의 .hwp 결과는 본문이 바뀌면 미리보기 글을 새 글로 바꾸고 미리보기 그림은 빈 그림으로 둡니다.
