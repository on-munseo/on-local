# 개인정보 찾기 다시 재기 — 공개 시험 korean-pii-benchmark-v3, npm 꾸러미만으로

공개 시험 [korean-pii-benchmark-v3](https://huggingface.co/datasets/schift-io/korean-pii-benchmark-v3)(CC-BY-SA-4.0, 473줄)를 **On 문서 내 PC 판(npm `on-munseo-local`)** 의 개인정보 도구로 읽고 정답과 맞대는 대본입니다. 비공개 코드는 쓰지 않습니다. 필요한 것은 공개 npm 꾸러미, 공개 자료 파일, 이 폴더의 대본 `run.mjs`(다른 꾸러미 없이 Node 만으로 돎)뿐이라 누구나 같은 숫자를 다시 낼 수 있습니다.

- 이 시험에는 공식 채점기와 순위표가 없습니다. 그래서 **채점 정의는 우리가 정했고**, 아래와 `run.mjs` 머리 주석에 그대로 적었습니다. 정답은 그 시험 자료에 붙은 표시를 그대로 씁니다.
- 자료는 허깅페이스 저장소의 커밋 `6dfeb331800d9c3b6318e40f92fe57d317e9ae3f` 로 고정해 받고, SHA-256 `0aa9303bff69b895bd4f29da451ac8f5c4a86220f80b1314cb9f7279a68279dc` 와 맞대 봅니다. 시험 문장은 합성 자료이지만 이 폴더에는 싣지 않습니다.

## 우리가 돌린 값(2026-11-28, `on-munseo-local@0.3.1`)

아래 결과와 `expected/` 는 **0.3.1 로 잰 값**입니다. 게시된 0.3.3 으로 다시 돌린 결과(2026-11-28)도 473줄 모두 `expected/` 와 같았습니다. 대본 기본값은 0.3.3 이므로, 아래 기록을 다시 내려면 `--pkg on-munseo-local@0.3.1` 을 줍니다.

| 종류 | 찾음률 | 정밀도 | 맞음 · 헛찾음 · 놓침 |
|---|---|---|---|
| 사람 이름 | **95.6%** | **100%** | 393 · 0 · 18(정답 411) |
| 주소 | **97.9%** | **100%** | 138 · 0 · 3(정답 141) |
| 전화번호 | 43.1% | 100% | 28 · 0 · 37(정답 65) |
| 주민·외국인등록번호 | 100% | 100% | 1 · 0 · 0 |
| 이메일 | 100% | 100% | 3 · 0 · 0 |
| 회사 이름 | 0% | — | 이 도구가 찾는 종류가 아님(정답 182) |

- **가리면 안 되는 문장 59줄 가운데 가린 줄: 0**(법령 이름·사건 번호·직위만 있는 문장 등).
- 이름·주소·가리면 안 되는 문장 값은 [측정 자료](https://github.com/on-munseo/on-munseo.github.io/blob/main/docs/benchmark.md) 5.4절에 적은 서버 판 값(이름 95.6%·정밀도 100%, 주소 97.9%·100%, 59건 중 0)과 같습니다. 서버 판과 같은 모델·같은 규칙이 이 꾸러미 안에 있고, 문서는 이 컴퓨터 밖으로 나가지 않습니다.
- 전화번호를 많이 놓치는 것은 지역번호로 시작하는 일반 전화(예: `02-123-4567` 꼴)를 이 판이 가리지 않기 때문입니다. 휴대전화는 가립니다. 이 값은 측정 자료에 따로 적지 않았던 약점입니다.
- 같은 꾸러미로 다섯 번 돌렸습니다. 허깅페이스에서 새로 받아 두 번, 받아 둔 사본으로 Node 25.9 두 번, Node 22.17 한 번입니다. 다섯 번 모두 473줄의 찾은 자리가 같았습니다(줄별 지문 `expected/rows.sha256` 의 SHA-256 `d62c2966…82e18fa`).
- 앞 판과도 같습니다 — 0.2.1(2026-11-27, 다섯 번 — 0.2.0 한 번 포함)·0.3.0(공개판 묶음)도 473줄 찾은 자리가 모두 같았습니다(같은 줄별 지문).
- 473줄을 도는 데 1초 안쪽이었습니다(맥북 M5 Pro, 꾸러미를 띄우는 시간 뺌).

## 다시 재는 순서

필요한 것: Node.js 20 이상. 다른 꾸러미는 깔지 않습니다.

```sh
node run.mjs --pkg on-munseo-local@0.3.1                                   # 고정 커밋에서 자료를 받아(cache/) 지문을 확인하고, 측정 기록의 0.3.1 로 473줄을 잼
node run.mjs --pkg on-munseo-local@0.3.1 --data <받아 둔 benchmark_v3.jsonl> # 받아 둔 파일로(지문은 그대로 확인)
node run.mjs --pkg on-munseo-local@<판>                                    # 다른 판으로 — 판이 다르면 값이 달라질 수 있고, expected/ 와 다른 줄을 알려 줌
```

- 끝에 종류별 값과 함께 이 폴더 `expected/rows.sha256` 과 맞대 「473줄 모두 같음」인지, 다르면 몇 번째 줄인지 알려 줍니다.
- 결과는 `out/` 에 씁니다: `summary.json`(종류별 셈), `result.json`(줄마다 찾은 자리 `[시작, 끝, 종류]`·도구 둘이 센 개수가 같은지 — 문장 글은 싣지 않음), `rows.sha256`.
- 인터넷은 자료를 받을 때와 npx 가 꾸러미를 받을 때만 씁니다. 꾸러미는 글을 이 컴퓨터 안에서만 다룹니다. Node 25 이상이면 Node 가 꾸러미의 네트워크를 막습니다.

## 어떻게 맞음을 가리나

1. **찾은 자리 되살리기.** `on_find_pii` 는 값 전체도 글자 자리도 돌려주지 않습니다(종류·개수·가린 보기·몇 번째 문단). 그래서 같은 글을 `on_mask_text` 에 넣어 가린 글을 받고, 원문과 맞대 어느 자리가 무엇으로 가려졌는지 되살립니다.
   - 가린 꼴과 종류: `○○○` → 사람 이름 · `[주소 가림]` → 주소 · `[전화번호 가림]` → 전화번호 · `[주민번호 가림]` → 주민·외국인등록번호 · `[이메일 가림]` → 이메일. `[번호 가림]`(계좌·차량·카드 등)은 이 시험의 정답 종류가 아니어서 셈에서 뺍니다(이번에는 0개).
   - 가린 자리 밖의 글은 원문과 한 글자도 다르면 안 됩니다. 맞지 않으면 그 줄을 「맞대기 실패」로 적습니다(이번에는 0줄). 원문에 이미 「○○○」로 적힌 글은 가린 것이 아니라 원문 그대로로 봅니다.
   - 가린 꼴 둘이 붙어 있으면 어디서 나뉘는지 알 수 없어 맞대기 실패로 적습니다. 이 시험에는 정답 자리끼리 붙은 곳이 없습니다.
2. **도구 둘이 같은지.** 줄마다 `on_find_pii` 가 센 종류별 개수와 되살린 자리의 종류별 개수를 맞댑니다. 473줄 모두 같았습니다.
3. **맞음.** 같은 종류이고, 겹친 글자 수가 정답과 찾은 것 가운데 짧은 쪽 길이의 절반을 넘으면 맞음입니다. 하나는 한 번만 짝짓습니다.
   - 정답이 있는 줄에서 짝 없는 찾은 것은 헛찾음입니다.
   - 정답이 하나도 없는 줄(가리면 안 되는 문장)에서 하나라도 찾으면 「가릴 것이 없는데 가림」 한 줄로 셉니다.
   - 찾음률 = 맞음 ÷ (맞음 + 놓침), 정밀도 = 맞음 ÷ (맞음 + 헛찾음).

## 한계

- **공개 473건은 놓친 꼴을 보고 규칙·학습 자료를 고칠 때 본 시험이라 실제보다 높게 나올 수 있습니다.** 처음 보는 문서에서는 더 낮을 수 있습니다. 모델 학습에 쓰지 않은 날짜의 관보 조각으로 잰 값(측정 자료 5.4절)은 원문을 싣지 않아 이 대본에 들어 있지 않습니다.
- 정답은 이 시험 자료의 표시입니다. 이름 경계·주소 범위를 우리와 다르게 잡은 곳이 있을 수 있고, 그런 곳은 놓침이나 헛찾음으로 셉니다.
- 채점 정의는 우리가 정했습니다. 겹침 기준을 바꾸면 값이 달라집니다.
- 시험 문장은 합성 자료입니다. 실제 공문서·판결문과 꼴이 다를 수 있습니다.
- 일반 전화(지역번호)는 이 판이 가리지 않습니다. 회사 이름은 찾지 않습니다.
- 우리가 만든 대본으로 우리가 잰 값입니다(자체 측정). 다만 공개 꾸러미·공개 자료·이 대본만으로 같은 값이 다시 나옵니다.

## 이 폴더의 파일

| 파일 | 내용 |
|---|---|
| `run.mjs` | 다시 재는 대본(Node 20 이상, 다른 꾸러미 없음) |
| `expected/summary.json` | 우리가 낸 종류별 셈·자료와 꾸러미 판 |
| `expected/rows.sha256` | 줄마다 찾은 자리의 지문(`<SHA-256>  <줄 번호> <원문 SHA-1>` — 문장 글은 싣지 않음) |
| `expected/environment.json` | 꾸러미 지문(SHA-256·npm integrity)·자료 커밋·돌린 환경 |
